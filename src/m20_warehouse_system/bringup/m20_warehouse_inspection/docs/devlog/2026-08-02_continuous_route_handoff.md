# 2026-08-02 M20 净空路线连续交接

## 背景

主动净空 A* 已解决“原生路线先驶入不可转弯窄道、后备接管过晚”的问题，但此前每个
压缩子目标都无条件触发 `/m20/control/route_segment_hold`。即使前后只有几度方向差，
也必须减速到零、稳定 0.30 s、发布下一目标再释放，表现为明显的分段启停。

本轮保留已经验证的全局路径、硬/软净空和危险拐点停稳机制，只改变相邻子目标的交接
决策；第三方 `src/third_party/SCAN-Planner` 没有修改。

## 几何策略

每个中间子目标根据前一点、当前点和后一点独立分类：

1. 方向变化不得超过 `0.70 rad`；
2. 依据官方策略冷启动测试得到的 `0.54 m` 最小中心线转弯半径，检查圆角在前后两段
   所需的切线长度 `R * tan(theta / 2)`；
3. 从当前点前方 `0.70 m` 的理想交接位置到下一子目标的整条栅格线必须保持自由；
4. 该线除位于既有 `0.60 m` 硬膨胀之外，还要保留至少 `0.10 m` 额外净空。

分类为连续时，在距离当前逻辑子目标 `0.55 m` 处直接发布下一 SCAN 目标。SCAN FSM
处于执行态，会以当前轨迹导数重新规划连续 B-spline；适配器不拉起 segment hold。
分类为停止时，仍使用原有实测速度阈值、稳定时间、超时和锁存安全保持。

`0.893 m` 是最小半径转弯相对转弯中心的外角扫掠诊断值，不等于“障碍物再膨胀
0.893 m”。硬层已经约束中心路径和机身保守包络，因此本轮没有把外扫值重复叠加到
圆形障碍膨胀；最小半径与连续捷径碰撞检查分别承担运动学和环境几何约束。

## 模块改动

- `m20_scan_navigation/grid_route.py`
  - 新增单拐点连续可行性检查；
  - 新增与子目标等长的连续/停稳分类表。
- `m20_scan_navigation/grid_route_node.py`
  - 连续拐点使用提前交接半径；
  - 危险拐点保留 stop-to-stop；
  - 日志输出连续交接数量。
- `m20_warehouse_inspection/boundary_recovery_probe.py`
  - 记录每次下一目标发布前是否出现 segment hold；
  - 只对要求停稳的交接检查 0.30 s 稳定窗口，连续交接单独计数。

所有阈值集中在 `config/f1_grid_route.yaml`，后续实机可通过配置收紧，不需修改第三方
规划器或任务代码。
