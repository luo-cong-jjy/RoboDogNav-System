# 第 1 阶段开发记录：地图与 RViz 双区域静态基线

日期：2026-07-27  
版本：0.2.0  
状态：完成

## 1. 本阶段目标

- 系统配置在进入节点前完成 schema、几何和跨引用校验。
- 使用固定 seed 生成 F1/F2 点云、栅格和元数据。
- RViz 同时显示两块 `z=0` 平面区域。
- 规划输入的 active map 初始只包含 F1。
- 不修改 SCAN-Planner、Gazebo、MuJoCo、M20 SDK 和现有功能包。

## 2. 坐标决策

地图资产使用每层局部坐标：

```text
x: [-20, 20]
y: [-20, 20]
z: [0, 2]
```

发布到平面仿真时施加：

```text
F1 offset: [-25, 0, 0] -> x [-45, -5]
F2 offset: [ 25, 0, 0] -> x [  5, 45]
```

因此两块区域均在 `z=0`，中间净间隔 10 m，但资产本身不固化该仿真偏移。后续实机可
直接使用各层局部地图，任务层必须依赖 floor ID，不能根据 x 坐标猜测楼层。

## 3. 配置校验

新增校验内容：

- `schema_version`、必需模块和基础类型。
- 平面双区域模式、正数尺寸/分辨率、禁止直接跨区。
- 楼层数量、唯一 seed、唯一且安全的相对资产路径。
- `simulation_offset.z == overview_z == ground_z`。
- 楼层区域互不重叠且满足最小间距。
- 起点、电梯点、reserved zone 和巡检点均在对应区域内。
- 电梯源/目标楼层、任务点和 mission sequence 引用有效。

生成器命令行入口在首次 colcon 构建前也能运行；没有 ROS 包索引时，从源码模块位置
解析默认项目根目录。

## 4. 地图生成算法

每层使用独立 `numpy.random.Generator` 和配置 seed：

1. 把配置中的仿真展示点转换回楼层局部坐标。
2. 为起点、巡检点、电梯区和连接走廊建立 protected rectangles。
3. 在边界内拒绝采样 180 个互不重叠的小型矩形障碍。
4. 以 0.10 m 表面分辨率采样边界墙、障碍侧面和顶面。
5. 去除重复点，写出 `x y z intensity` ASCII PCD。
6. 生成 `400 × 400`、0.10 m/cell 的 PGM/YAML 占据栅格。
7. 使用四连通 BFS 验证任务点、电梯点和起点可达。
8. 写出障碍、边界、坐标约定、点数和文件 SHA-256 元数据。
9. 重新读取所有资产，校验 PCD 头、点数、边界、PGM 尺寸和哈希。

相同配置和 seed 的测试生成执行两次，并断言哈希一致。F1/F2 使用不同 seed，并断言
PCD 哈希不同。

## 6. ROS 2 地图服务器

`m20_flat_map_server` 启动时完成：

- 校验系统配置和两层全部资产。
- 预加载 F1/F2 PCD。
- 发布合并后的 RViz 总览点云。
- 默认仅发布 F1 active cloud 和 F1 occupancy。
- 发布 `active_floor=F1`、`generation=1`、`ready=true`。
- 发布 F1/F2 边界、文字和 active/inactive Marker。
- 发布 `warehouse_overview -> map` 的静态单位变换。

所有静态地图和状态使用：

```text
reliability: reliable
durability: transient_local
history: keep_last
depth: 1
```

阶段 1 不提供运行时切图服务，避免形成不带停止、reset、generation 和失败保持的临时
接口。

## 7. RViz

`flat_multifloor.rviz` 固定 frame 为 `warehouse_overview`，显示：

- F1/F2 合并总览点云。
- 黄色高亮的 active F1 点云。
- 两层边界和 `F1 ACTIVE`、`F2 INACTIVE` 标签。
- 可选但默认关闭的 active occupancy。

启动入口：

```bash
ros2 launch m20_warehouse_inspection flat_multifloor_rviz.launch.py
```

无 GUI：

```bash
ros2 launch m20_warehouse_inspection \
  flat_multifloor_rviz.launch.py use_rviz:=false
```

## 10. 节点级验收

在 CycloneDDS、`ROS_LOCALHOST_ONLY=1` 下执行无 GUI启动和 transient-local 话题读取：

```text
published system topics: 7
active_floor: F1
generation: 1
ready: true
all_floors_cloud.width: 290706
active_global_cloud.width: 144742
active_occupancy: 400 × 400, 0.10 m/cell
active_occupancy origin: [-45, -20, 0]
markers: F1 ACTIVE, F2 INACTIVE
```

沙箱内禁止 DDS 创建 socket，因此通信验收在获准的沙箱外本机 loopback 上完成；运行
内容没有访问外部网络。

另执行了 12 秒实际 RViz 启动检查：RViz2 正常创建窗口并加载 OpenGL 4.2，未报告
RViz 配置、PointCloud2 显示或 MarkerArray 插件错误；随后由超时器自动关闭。
