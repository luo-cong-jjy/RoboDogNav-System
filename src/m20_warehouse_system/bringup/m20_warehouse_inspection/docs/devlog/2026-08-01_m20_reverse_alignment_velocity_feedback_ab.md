# 2026-08-01 M20 直线倒车判定与速度反馈复验

## 目标

在不修改 SCAN 地图、A*、B-spline、碰撞半径和重规划参数的前提下，继续收敛
M20 运动执行层的两个问题：

1. 曲线路径不能因为首个局部切向位于机身后方就被误判为倒车；
2. 实测速度反馈只有在证明不降低绕障安全余量后，才允许成为默认能力。

本轮仍使用官方 M20 MJCF、官方 ONNX 策略和项目 `CmdVelInterface`，没有把
MuJoCo 动力学结果替换为质点或自行设计的轮腿控制器。

## 问题复现

第一轮六目标冷启动暴露了两种不同故障：

- 右后方曲线被单点切向判断为 `REVERSE`，官方策略在不适合倒车的曲线上出现
  `EXCESSIVE_TILT`；
- 直线倒车接近 B-spline 末端时，退化切向在 100 Hz 控制循环内使状态从
  `REVERSE` 跳回 `FORWARD`，机器人随后偏离并超时。

这两项都属于 M20 轨迹执行方向选择，不是 SCAN A* 或障碍膨胀参数问题。

## 实现调整

### 1. 仅允许近似直线轨迹倒车

`m20_scan_planner/closed_loop_controller.cpp` 现在只在收到新 B-spline 时更新跟踪
方向，并对轨迹前段的起点、中点和末点切向采样。只有所有非退化切向都与机身后轴
对齐时，才允许进入 `REVERSE`。曲线重规划会退出倒车。

倒车开始时锁存当前机身航向。倒车期间沿同一世界坐标 B-spline 输出负向机体系
速度，但不跟随末端退化切向反复旋转。独立 SCAN 启动仍默认关闭这项 M20 能力。

### 2. 扩展动态探针

`navigation_motion_probe.py` 数据格式升级到 schema 6，新增：

- 参考速度与实测速度的线速度、角速度 RMS；
- 速度反馈 active 比例和原因计数；
- PI 修正量 RMS 与峰值；
- backend fault、碰撞保护、恢复和实体接触的统一统计。

这些数据用于区分“指令跟踪更准”和“几何路径更安全”，两者不能互相替代。

### 3. 速度反馈门控

实验分三步缩小作用范围：

1. 全程 PI；
2. 仅 `WHEEL_CRUISE`；
3. 仅 `WHEEL_CRUISE` 且参考角速度绝对值不超过 `0.08 rad/s`。

转弯、横移、执行保持和停车阶段均清空积分并旁路反馈，诊断原因为
`MANEUVER_GATED`。修正后的命令仍位于 collision guard 上游。

## 决策

近似直线门控版本在开阔六目标中优于开环基准，但第一次单障碍冷启动把最小 SCAN
硬边界余量从 `0.2359 m` 降到 `0.1645 m`；第二次重复则达到 `0.2508 m`。
同配置的绕行侧和安全余量仍有显著随机性，当前样本不足以证明生产安全性。

因此：

- 直线倒车修复进入完整 M20 默认执行链；
- `velocity_feedback_cruise_only: true` 和 `0.08 rad/s` 门控保留；
- `velocity_feedback_enabled` 继续默认 `false`；
- 不修改 SCAN 规划、膨胀和净空参数来补偿运动反馈的波动。

完整数据与量化结论见
`docs/test_reports/2026-08-01_m20_velocity_feedback_requalification.md`。
