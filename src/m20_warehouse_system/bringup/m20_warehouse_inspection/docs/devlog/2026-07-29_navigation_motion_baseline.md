# MuJoCo自由导航轮腿协同基线分析

日期：2026-07-29

## 目的

验证当前完整系统在无明显障碍威胁的直线、90°和180°目标中能否完成自由导航，
并区分以下三个现象：

1. SCAN轨迹本身是否明显摆动；
2. SCAN闭环控制器是否持续输出小幅方向修正；
3. 官方ONNX策略是否在轮子滚动时同时驱动腿部关节。

本轮只诊断和建立基线，没有修改SCAN算法、速度适配参数或官方ONNX策略。

## 系统链路

测试使用正式入口：

```bash
ros2 launch m20_warehouse_inspection \
  inspection_mission_mujoco.launch.py
```

运行条件：

- 正式0.90 m `dense_four_corner`双场景；
- 原生SCAN规划和B样条轨迹；
- `clearance_conservative`净空档；
- 官方M20 ONNX策略；
- MuJoCo 16关节接触动力学；
- RViz和MuJoCo原生跟随窗口均开启。

测试工具为`tools/navigation_motion_probe.py`。它通过原版
`/move_base_simple/goal`入口发送目标，并以约20 Hz记录：

- 原始、安全和SDK三层`Twist`；
- MuJoCo机身位姿；
- 12个腿部关节和4个轮子关节的实际速度；
- `WHEEL_CRUISE / COORDINATED_TURN / LATERAL_MANEUVER`意图；
- 碰撞停止、接触数量和SCAN B样条发布次数。

## 测试路线

F1内依次执行六个目标：

```text
(-37, 0) -> (-34.5, 0) -> (-37, 0)
-> (-37, -6) -> (-34, -6) -> (-37, -6) -> (-37, 0)
```

静态检查确认三类直达线段的最近障碍物本体距离分别不小于1.165 m、1.644 m和
0.987 m。本测试用于观察无障碍威胁下的运动控制，不是绕障压力测试。

## 轮腿接口审计

官方部署策略每约20 ms构造一次57维观测，并一次输出16维动作：

- 12维腿部关节位置目标；
- 4维轮子速度目标。

部署代码在同一个`getRobotAction()`调用中同时写入
`goal_joint_pos`和`goal_joint_vel`。项目的运动意图枚举只约束进入策略的
`forward/side/yaw`速度，不会选择“只用轮子”或“只用腿”的另一套网络。

因此轮子和腿不是互斥执行器。即使输入为纯前进，ONNX仍可改变腿部位置来保持机身
姿态、轮荷分配和接触稳定。强制锁死12个腿部关节而只保留4个轮速会改变策略训练时
的动作空间，不能作为安全的参数微调。

## 定量结果

六组目标均成功，最终误差为0.152～0.192 m，没有碰撞停止样本。完整数据见：

- `artifacts/navigation_motion/2026-07-29_baseline/navigation_motion_samples.csv`
- `artifacts/navigation_motion/2026-07-29_baseline/navigation_motion_summary.json`

全部运动采样的意图占比：

| 意图 | 占比 |
|---|---:|
| `WHEEL_CRUISE` | 26.62% |
| `LATERAL_MANEUVER` | 63.81% |
| `COORDINATED_TURN` | 9.57% |

以腿部最大关节速度大于0.05 rad/s、轮子最大速度大于0.20 rad/s作为“明显参与”
阈值，全部运动采样中轮腿同时参与比例为81.76%。

在两段筛选出的纯滚动采样中，SDK输入满足`vy=0`、`wz=0`且`vx>0.15 m/s`：

| 数据段 | 腿部最大速度均值 | 轮子最大速度均值 | 轮腿同时参与 |
|---|---:|---:|---:|
| 首段短直线 | 0.372 rad/s | 2.720 rad/s | 100% |
| 6 m直线稳定段 | 0.315 rad/s | 5.455 rad/s | 100% |

这说明用户在窗口中看到的腿部小幅调整不是仅由障碍物或规划弯线触发；它也存在于
完全没有侧向和偏航速度输入的官方策略滚动阶段。

## “不够优雅”的主要来源

### 1. 直线阶段仍有连续偏航反馈

首段2.5 m直线最大横向偏离仅0.045 m，说明几何路线本身较直；但实际平均航向误差
为2.12°、95分位为4.14°。闭环控制器的偏航命令RMS为0.079 rad/s，84.8%的
运动采样超过0.02 rad/s。官方策略会用轮速差和腿部姿态共同跟踪这些小修正。

### 2. 当前接口过多进入横移意图

SCAN控制器输出机体系`vx/vy/wz`。当前运动意图先判断`abs(vy)>=0.05 m/s`，
满足后直接进入`LATERAL_MANEUVER`。转向后的路径跟踪中，机身方向和世界系轨迹方向
尚未完全对齐，因而经常出现短时`vy`；本轮63.81%的运动采样被归为横移。

横移档会把前进速度限制到0.10 m/s并保留侧向速度，ONNX自然产生更明显的轮腿协同
动作。这是目前“边小幅前进、边明显动腿”的首要可调接口原因。

### 3. 180°回程并非零半径点转

两个180°回程目标虽然没有碰撞，但相对直达线的最大横向偏离分别为0.611 m和
0.564 m，路程比分别为1.520和1.416。当前策略通过差速轮、侧向动作和腿部重心调整
共同完成转向，不能按平面质点的零扫掠原地旋转计算狭窄空间。

## 建议的下一步

不应先修改SCAN规划数学主链，也不应锁死腿部动作。建议新增一个可回退的
`rolling_navigation`速度适配候选，在SCAN控制器与官方ONNX之间完成：

1. 自动导航默认把`vx/vy`合成为路径切向速度和附加航向误差；
2. 正常巡检禁止横移，将侧向误差转换为前进加偏航；
3. 大航向误差时先进入协调转向，再恢复滚动；
4. 为模式切换增加进入/退出迟滞，避免在0.05 m/s边界抖动；
5. 为巡航偏航加入小死区、低通和角加速度限制；
6. 保留人工明确横移命令的独立入口；
7. 用本轮同一六目标数据做A/B对照，不用主观窗口观感替代指标。

该方案保留官方策略对腿部稳定性的控制权，但应显著减少导航层不必要的横移和
频繁方向微调。
