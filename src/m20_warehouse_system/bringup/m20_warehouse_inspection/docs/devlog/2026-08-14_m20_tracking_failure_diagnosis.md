# M20 路径跟踪失准复核与实验回退

日期：2026-08-14

## 结论

本轮针对“RViz 中曲线可见，但 MuJoCo M20 跟踪误差大并在首个障碍处停住”进行
同目标复验。测试目标为 `(-26.5977, -4.89832)`，固定失败障碍为
`F1_0046`：中心 `(-32.3261, -1.8743)`，半尺寸约
`(0.4160, 0.3828)`。

问题不能归结为单一控制增益：原时间参数化控制确有参考超前，但把执行改成实测
空间进度后，M20 仍在同一实体障碍处接触。接触末期的速度参考换算到世界坐标后仍
指向障碍内部，说明该任务同时存在局部 B 样条/实体扫掠包络不可执行问题。仅继续
降低速度、冻结轨迹时钟或增大反馈增益不能闭环解决。

## 已验证事实

- 原速度链的历史同目标结果存在较大航向跟踪误差；当前默认速度上限为
  `0.45/0.20/0.65`。
- 实测空间投影实验可把轨迹位置误差显著压低，但仍在 `F1_0046` 接触并超时。
- 二值时钟冻结在 M20 的稳态摆动下形成死锁，轨迹进度仅约 2.5% 时间处于运行态。
- 连续实测相位若没有局部搜索和位移约束会误跳到未来曲线段；补齐约束后不再误跳，
  但仍不能越过同一障碍。
- 将双圆硬半径从 `0.28 m` 试增至 `0.35 m`、同时保持总名义单侧带
  `radius + dist0 = 0.45 m`，没有消除该接触。
- 横向误差降速和动态缩短前视距离把航向误差均值/P95 降至约
  `1.54°/3.39°`，但 120 秒后仍停在 `(-33.188, -1.852)`；实体障碍接触事件
  仍为 2196 次。

## B 样条与占据输入只读核验

对 `/tmp/m20_first_bspline.yaml` 中轨迹 `traj_id=2` 均匀采样 10001 点，
并使用当前 M20 双圆包络 `radius=0.28 m`、`offset=0.18 m` 与
`F1_0046` 的 MuJoCo 实体 AABB 比较，结果为：

- 障碍实体边界：`x=[-32.7421,-31.9101]`、
  `y=[-2.2571,-1.4914]`；
- B 样条中心线本身进入了实体 AABB；
- 双圆包络最小净距为 `-0.2800 m`，即圆心已进入实体，而不是仅擦到安全裕度；
- 扫掠相交时间段约为轨迹时间 `12.425~20.539 s`。

随后在隔离域执行无目标、无界面的完整链路快照。地图服务器和原生 renderer 已输出
`Global point cloud received`、`Normal computation finished`，MuJoCo 也已 ready；但
采样窗口内 `/quad_0/cloud` 没有收到一帧，`/grid_map/occupancy` 与
`/grid_map/occupancy_inflate` 收到的快照均为 0 点。与此同时，当前
`scan_vendor_local_sensing.yaml` 配置了 `plane_interline: 0`，原生 renderer 源码却
没有声明/读取这个参数，配置实际未生效。

因此本次复现不能只归因于 M20 跟踪增益。实际链路至少同时存在：

1. 原时间参数化控制对物理 M20 产生参考超前；
2. 原生仿真点云首帧/持续发布存在不确定性，系统允许在占据图为空时接收目标；
3. 空占据图生成的 B 样条会直接穿过 MuJoCo 实体，随后无论控制误差多小都会接触。

曾尝试只补齐 `plane_interline` 参数读取并完成编译，但动态复验启动被当前执行环境的
系统额度限制拒绝。该未验证源码修改已撤回，`local_sensing_node` 已按撤回后的源码
重新构建，未把候选修复留在默认系统中。

## 回退状态

上述实测进度、规划 FSM 相位接口、动态前视和 `0.35 m` 包络均未通过完整动态验收，
已经撤回。主启动链恢复到本轮开始前的 M20 速度覆盖和 SCAN 执行语义：

- 规划上限 `0.45 m/s`；
- 控制上限 `0.45/0.20/0.65`；
- M20 双圆 `radius=0.28 m`、`offset=0.18 m`、`dist0=0.17 m`；
- 不保留新增的实测进度话题或控制器实验参数。

恢复后 55 项定向测试通过，三个相关包重新构建成功。隔离域无界面 MuJoCo 冒烟
启动进入 `backend ready` 和 `safety state: NAVIGATION`；20 秒超时 SIGINT 退出仍会
产生现有 Python 节点的关闭期噪声，不是运行期启动失败。

## 下一步边界

继续改控制器前，应先修复并验证原生点云 renderer 的首帧发布，同时让手动和自动目标
在 `/m20/sensing/state.ready=true` 且 GridMap 非空以前保持拒绝/等待。之后再增加
B 样条实体扫掠校验：对每条 `/planning/bspline` 按 M20 有向足迹采样，并与同一
时刻局部占据点云核对最小净距。验收判据必须区分：

1. 中心线/扫掠体本身不安全：修正局部目标、占据表达或 M20 规划包络；
2. 扫掠体安全但实测偏离：再启用实测速度闭环或空间进度跟踪。

在获得该判据前，不再把单次“看起来更顺”或单一误差下降当作导航通过。
