# 阶段 4 开发记录：typed 导航与自动巡检任务

日期：2026-07-27  
版本：0.5.0  
范围：导航 Action gateway、typed mission、暂停/恢复/停止/故障重试、任务安全保持、
RViz 任务状态、完整 F1→F2 自动任务验收  
不在本阶段：真实电梯协议、Gazebo 雷达/动力学、20 次切图压力测试、实机定位与 M20 SDK

## 1. 阶段目标

在阶段 3 已验证的楼内 SCAN 导航和原子楼层切换上增加稳定的任务编排边界。任务层不再
依靠反复发布 `PoseStamped` 或解析字符串日志，而是使用 typed Action：

```text
RunMission
  -> NavigateFloor(F1_A)
  -> NavigateFloor(F1_B)
  -> NavigateFloor(F1 elevator lobby)
  -> NavigateFloor(F1 elevator cabin)
  -> SwitchFloor(F1 -> F2)
  -> NavigateFloor(F2_A)
  -> NavigateFloor(F2_B)
  -> COMPLETED
```

验收要求：

1. 自动完成配置中的五个 mission step。
2. 每个导航目标绑定正确的 floor 和 map generation。
3. pause 能取消当前子导航、立即安全停车，resume 能从当前位置重新规划。
4. stop、cancel 或任务故障不能让旧导航速度恢复。
5. 原子切层期间不能停在不确定中间状态。
6. 目标、路线、SCAN 状态和新地图到达顺序存在竞态时仍 fail-closed。

## 2. 接口扩展

`m20_warehouse_interfaces` 增加：

```text
NavigateFloor.action
  goal_id + floor_id + map_generation + target_pose + timeout
  typed feedback
  success/final_distance/error_code result

NavigationState.msg
  当前 goal、楼层、代次、状态、剩余距离和原因

RunMission.action
  mission_id + restart
  MissionState feedback
  completed_steps/error_code result

MissionState.msg
  mission/step/floor/generation/paused/fault/message

ControlMission.srv
  PAUSE、RESUME、STOP、RETRY_CURRENT
```

接口包保持纯 rosidl，不依赖地图、SCAN、任务或仿真实现。

## 3. 导航 Action gateway

`m20_navigation_gateway` 对阶段 2/3 的 A* 路线适配器和 SCAN 做统一生命周期管理：

1. 接受前校验 map ready、floor 和 generation。
2. 调用 `/m20/navigation/route_reset` 清空 A* 路线及内部短子目标。
3. 调用 `/m20/navigation/reset` 清空 SCAN GridMap、目标和轨迹。
4. 等待路线状态 READY，再发布目标。
5. 持续反馈实际剩余距离和路线更新次数。
6. 根据位置、路线事件、取消、楼层变化或超时返回 typed result。
7. 退出时清理路线和 SCAN，避免下一个 Action 继承旧状态。

`m20_grid_route_planner` 增加独立 route reset 服务。地图或 hold 进入 not-ready 时立即
清除活动路线；新目标只能在当前 floor/generation 的 occupancy 已绑定后处理。

## 4. 自动任务与安全控制

`m20_mission_executor` 从系统 YAML 解析 typed `MissionStep`。inspection step 调用
导航 Action 并执行配置 dwell；elevator step 依次导航 lobby 和 cabin，再调用
`SwitchFloor`。先到 lobby 再进入 cabin 还能让最终航向自然对齐电梯触发方向。

控制语义：

- `PAUSE`：取消活动导航，等待子结果/reset 完成，断言 mission hold，进入 PAUSED。
- `RESUME`：释放暂停条件，从当前位置重新发送当前 step 导航。
- `STOP`：终止任务并保留 mission hold。
- `RETRY_CURRENT`：只在 `FAULT_HOLD` 接受，重试当前 step。
- Action cancel：与 stop 一样安全收口并保留 hold。
- elevator transfer：设置 atomic 标记，中途拒绝 pause。

`m20_safety_supervisor` 增加独立 transient-local
`/m20/control/mission_hold`。它与 floor-switch hold 互不替代，任一断言都立即输出
零速度并发布 `MISSION_HOLD` 或相应安全状态。

楼层事务还增加 committed-target 恢复路径：如果地图已经提交到目标楼层、但后续传送、
reset 或感知确认失败，retry 不再次执行 map CAS，而是重新完成目标位姿、导航 reset 和
新鲜感知确认，最后才释放 floor hold。

## 5. 集成竞态与修正

### 5.1 短暂路线事件被最新快照覆盖

初版 gateway 只保存 `/m20/navigation/global_route_state` 的最新字符串。一次目标拒绝后
route reset 很快又发布 READY，gateway 可能没有看到中间的 `REJECTED_*`。

修正为有序事件队列，并记录目标开始时的事件序号。gateway 只消费本目标之后的事件，
`NO_ROUTE`、`REJECTED_*` 和 `GOAL_REACHED` 不再被后续 READY 覆盖。

### 5.2 FloorState 与 occupancy 到达顺序

地图和 occupancy 是独立 DDS 话题。启动或切图时可能先收到 READY floor state，再收到
对应 occupancy，也可能顺序相反。初版路线节点在其中一种顺序下停留
`MAP_NOT_READY`。

修正为两侧回调都执行相同的 floor/generation 配对检查，并允许
`MAP_NOT_READY -> READY`。导航 gateway 在 route reset 后增加 READY 屏障，确保新目标
不会抢在地图绑定之前发布。

### 5.3 隔离环境中的外部 CLI 发现

当前执行环境中，独立启动的 ROS CLI 进程不能稳定发现 launch 子进程。为让验收本身
仍通过真实 ROS Action/topic 而不是函数级模拟，增加可选的 in-graph acceptance 节点，
由同一 launch 启动。该节点默认关闭，不进入生产运行图：

```text
run_acceptance:=false
acceptance_mode:=quick|full
```

quick 验证单个 typed 导航；full 验证五步任务、运行中 pause/resume、安全零速、
F2 generation 和最终距离。

```bash

export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
export CYCLONEDDS_URI=file://$(ros2 pkg prefix m20_warehouse_inspection)/share/m20_warehouse_inspection/config/cyclonedds_local.xml

  use_rviz:=false run_acceptance:=true acceptance_mode:=full
```

```text
  -> E1 cabin
```

## 8. 已知边界与下一阶段

- 本阶段只验证一次完整任务和一次中途 pause/resume，不等同于任务完成率 10/10。
- stop、cancel 和 fault retry 已实现并有静态/策略测试；系统级故障注入矩阵属于阶段 5。
- committed-target 恢复路径已实现，尚需逐故障点注入验证。
- 全任务约 4 分 36 秒，主要受 0.45 m/s 安全限速和路线长度影响，不代表实机性能。
- SCAN 在空闲 `WAIT_TARGET` 会持续输出状态日志，功能正确但后续可降低日志频率。
- Gazebo 和实机 profile 尚未接入；仿真 teleport 不允许用于实机。

注入、内存趋势和 Foxy/Humble 兼容回归。
