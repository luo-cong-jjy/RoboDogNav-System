# 2026-07-27 阶段 0 开发记录

## 本轮目标

根据讨论后的需求，先固化完整路线，再建立不会干扰现有功能包的新项目边界。

## 已确认需求

- M20 使用云深处官方模型资产。
- 当前优先完成 RViz，不做 Gazebo 同步。
- F1/F2 不是上下叠加的真实楼层，而是 `z=0` 平面上左右分离的两块区域。
- 两块区域面积相同、障碍布局可不同。
- 区域之间不允许普通导航穿越。
- 到达电梯触发点后停车、切 active PCD、清理导航缓存、平面传送并继续任务。
- 设计必须支持后续增加楼层和迁移实机。

## 仓库审计结论

- `m20_scan_planner` 已具备 M20 运动学仿真和 SCAN 局部规划闭环。
- 当前 `local_sensing_node` 只接受第一张全局点云，尚不能动态换图。
- SCAN GridMap 有内部 reset 能力，但尚无切图事务接口。
- 当前巡检状态依赖字符串，不适合多楼层事务。
- 当前安全节点的急停零速度仍会经过加速度限制，需要在正式安全模块中修正。
- 现有 `m20_scan_planner` 仍强依赖 Gazebo、M20 SDK 和多个第三方包，尚未达到独立
  工作空间要求。

## 本轮新增

- `m20_warehouse_inspection` ROS 2 包边界。
- 完整系统路线文档。
- 平面双区域系统配置契约。
- 初版接口契约。
- 固定版本第三方依赖清单。
- 第三方许可证记录和 Changelog。

## 本轮不做

- 不修改 SCAN、local sensing、Gazebo、MuJoCo 或 SDK 源码。
- 不生成最终 PCD。
- 不提供尚未完成的假 launch。
- 不启动 GUI。
