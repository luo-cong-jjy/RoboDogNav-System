## 1. 阶段目标

阶段 0～4 的运行结果来自当前综合工作空间。本阶段需要证明系统不依赖该工作空间中的
隐式 overlay，并把阶段 4 留下的单次验收扩展为可重复的系统级回归：

1. 从七个项目包和固定第三方 revision 重建独立源码树。
2. 在只 source `/opt/ros/humble` 的环境中构建完整依赖闭包。
3. F1↔F2 交替切换 20 次，检查地图代次、感知代次、保持零速和传送终点。
4. 生产速度执行五步完整任务 10 次，中间不重启节点。
5. 注入非法切层、旧代次、导航取消、任务停止和任务故障重试。
6. 对切图和任务循环采集项目进程总 RSS，拒绝持续无界增长。

`tools/prepare_isolated_workspace.sh` 只复制七个项目包，可选择在线 `vcs import` 或两个
本地 Git 镜像。脚本具有以下保护：

- 目标必须不存在或为空，拒绝覆盖已有工作空间；
- 不包含删除命令；
- checkout 后校验两个实际 Git revision；
- 在应用两个 SCAN 补丁前校验 SHA-256 和 `git apply --check`；
- 生成工作空间根级 `m20_workspace.lock`；
- 不复制任何 `build/`、`install/`、缓存或 pyc。

SCAN CPU 补丁把 `find_package(glm)` 限定到 `USE_GPU` 分支，并移除 CPU package
manifest 中仅 GPU renderer 使用的 GLM 强依赖。算法代码未修改。

后续新增的集成补丁将当前验证过的 SCAN 算法适配、楼层 reset、全局 PCD 热重载、
紧凑 PointCloud2 和可选可靠仿真传输固化到固定 revision，保证独立工作空间不会
退回只含 CPU 补丁的上游状态。

本阶段还纠正了第三方许可证记录：SCAN 仓库根许可证及所用 planner 包声明为

## 4. 回归框架

新增 `phase5_regression.launch.py` 和 in-graph 回归节点，保留阶段 4 的实际
map、local sensing、A*、SCAN、闭环控制、安全、仿真和任务节点，不用函数级模拟替代
ROS 通信。

### 4.1 切图压力测试

每次切换：

1. 在 e-stop 下通过仿真专用服务准备电梯触发位姿。
2. 发送 typed `SwitchFloor` Action。
3. 断言 floor generation 只加一。
4. 断言 sensing floor/generation 与 active map 完全一致且 ready。
5. 断言 floor-switch hold 只出现一个窗口。
6. 确认连续三个零 `cmd_vel_safe` 后，该保持窗口内不得再出现非零命令。
7. 断言机器人到达目标楼层 release pose。

最初用“收到 hold 后的第一条速度”判断零速，DDS 跨话题顺序可能让 hold 先于发送队列中
最后一条旧速度到达，从而产生假阳性。修正为连续三条零速度建立保持屏障，之后任何非零
仍判失败；每次事务必须恰好形成一个这样的零速窗口。

### 4.2 任务压力测试

每轮运行配置中的真实五步任务：

```text
F1_A -> F1_B -> E1:F1→F2 -> F2_A -> F2_B
```

除最后一轮外，在任务完成后通过同一 `SwitchFloor` Action 反向切回 F1，再从 F1 初始
位姿启动下一轮。节点图和 SCAN 进程不重启，因此 generation、缓存和内存状态跨轮累积。

### 4.3 故障注入

系统级覆盖：

- 不在电梯触发区发送切层，要求 `ERROR_NOT_AT_TRIGGER` 且 generation 不变；
- 发送未来 generation 的导航，要求拒绝；
- 运行中取消有效导航，要求 `ERROR_CANCELLED`；
- 运行中停止任务，要求 `ERROR_STOPPED + MISSION_HOLD + 连续零速`；
- 在错误楼层重启任务，要求进入 `FAULT_HOLD`；
- 反向切回正确楼层后 `RETRY_CURRENT`，要求恢复到 `NAVIGATING`，再安全停止。

### 4.4 内存趋势

回归器读取自身 `PPid`，只汇总同一个 launch 父进程直接启动的节点 RSS；因此并行的
colcon、编辑器或其他工作空间进程不会污染样本。随后计算：

```text
first
last
peak
last - first growth
线性最小二乘 slope / iteration
```

默认边界是总增长不超过 128 MiB，斜率不超过 8 MiB/轮。该指标用于发现明显的地图、
KdTree、轨迹或 Action 生命周期泄漏，不替代后续 ASan/LSan。

启动后的第一次完整事务会初始化 DDS、PCL 和 allocator 缓存。回归器同时输出包含启动
预热的 raw trend 和排除第一次事务后的 steady trend，阈值只约束 steady trend；这样
单次冒烟不会把一次性预热误判为“每轮泄漏”，多轮测试仍检查持续增长。

## 5. 独立构建和自动测试

严格清理 overlay 后只加载系统 ROS：

```bash

source /opt/ros/humble/setup.bash

colcon build --symlink-install \
  --packages-up-to m20_warehouse_inspection \
  --cmake-args -DCMAKE_BUILD_TYPE=RelWithDebInfo
```

## 7. 已知边界与下一阶段

- 本阶段是 Humble 主基线；Foxy 已于 2023 年 EOL，未在当前 Ubuntu 22.04 主机上构建。
- RSS 是进程级粗粒度趋势，不区分 allocator 缓存与真实泄漏。
- SCAN 第三方代码仍有编译 warning 和高频 FSM 日志，但未影响构建或回归。
- 高 INFO 日志压力下仿真 safety supervisor 偶发一个周期 `ODOM_STALE`，下一条 odom
  即恢复且期间 fail-closed 为零速；进入 Gazebo 性能验收前需量化并消除此调度抖动。
- 当前定位、点云和位姿传送都是 RViz 平面仿真 profile。
- Gazebo 同步、真实雷达和 SDK 不得混入当前已验证的平面基线。

下一阶段进入 Gazebo：先只替换运动/odom 后端并继续使用已验证 PCD local sensing；
通过同一任务、安全和楼层事务回归后，再接 Gazebo ray/LiDAR。
