# 2026-07-31 M20 机体系速度闭环 A/B 报告

## 结论

有界机体系速度闭环已在官方 M20 SDK MuJoCo 后端完成单障碍 A/B、三次闭环冷启动
和六目标开闭环对照。闭环能改善单次速度跟踪，但三次重复试验的最差 guard 净空只有
`74.6 mm`；六目标闭环在第 5 段 180° 返回时超过 `90 s`，只完成 4/6，而开环
完成 6/6。因此闭环不提升为主启动默认值。

## 对照条件

- 场景：`single_obstacle_direct_bypass`
- 系统配置：`clearance_direct_system.yaml`
- 运动后端：官方 M20 SDK 策略 + 无界面 MuJoCo
- 导航：vendored SCAN-Planner 当前冻结参数
- 碰撞保护：当前冻结的 M20 双圆预测保护
- 唯一实验变量：`velocity_feedback_enabled`
- 每组均为独立冷启动

## 判定

闭环达到了“可运行、无硬安全违规、跟踪误差改善”，但没有达到开发方案预设的
“guard 净空不降低”。由于 SCAN 局部轨迹在独立冷启动间可能不同，单次 A/B
不足以区分反馈影响与轨迹样本差异。生产默认继续使用开环运动适配：

```yaml
velocity_feedback_enabled: false
```

闭环接口、诊断和参数全部保留；下面的重复冷启动与六目标回归是后续完成的正式放行门，
其结果否决了本组参数的默认提升。

## 六目标严格对照

随后在 `dense_four_corner_system.yaml` 的同一 F1 区域、相同六目标、相同
`90 s` 单目标超时下分别冷启动闭环和开环。两组都没有 MuJoCo 障碍接触。

| 目标 | 开环 | 闭环 | 开环/闭环横向最大偏离 |
|---|---:|---:|---:|
| 直线前进 2.5 m | `9.69 s` PASS | `9.64 s` PASS | `0.017 / 0.017 m` |
| 180° 返回 2.5 m | `14.89 s` PASS | `15.17 s` PASS | `1.245 / 1.296 m` |
| 右转 90°前进 6 m | `24.31 s` PASS | `22.72 s` PASS | `0.529 / 0.641 m` |
| 左转 90°前进 3 m | `12.95 s` PASS | `13.68 s` PASS | `0.249 / 0.338 m` |
| 180° 返回 3 m | `72.31 s` PASS | `90.00 s` TIMEOUT | `0.793 / 0.796 m` |
| 左转 90°返回 6 m | `26.36 s` PASS | 未执行 | `0.665 / -- m` |

开环 6/6 到达，总用时 `160.49 s`；闭环在验收门限内只完成 4/6。关键第 5 段：

- SCAN 发出纯偏航 `raw=(vx=0, wz=-1)`；
- 开环出现 1015 个 `0.05 s` 碰撞停车样本，约 `50.8 s`；
- 闭环出现 1581 个碰撞停车样本，约 `79.1 s`；
- 两组都没有实体接触，运行诊断观察到的是预测足迹停车而非实体接触；
- 保护器反复在预测停车与后退恢复之间切换；
- 闭环探针超时后系统继续运行，最终也抵达目标，但已超过 `90 s` 验收门。

这说明长时间恢复并非 PI 单独产生，当前开环运动适配同样存在纯偏航与预测保护的
接口冲突。单次六目标 A/B 不能排除 SCAN 冷启动轨迹差异，但闭环组的恢复样本和超时
结果更差，已经足以否决其默认放行。

## 最终放行结论

`velocity_feedback_enabled` 明确保留为 `false`。当前 PI 参数不得用于生产默认或
完整巡检。下一步不继续提高 PI 增益，而应先：

1. 为 SCAN 纯偏航命令建立 M20 可执行的受限转向投影；
2. 防止预测恢复的后退命令把机器人持续带离目标；
3. 给恢复状态增加进展监测、距离/时间上限和强制重规划；
4. 扩展六目标探针，记录碰撞原因、反馈补偿和恢复阶段；
5. 修复后先用默认开环通过 6/6 且零长期恢复，再重新评估速度闭环。
