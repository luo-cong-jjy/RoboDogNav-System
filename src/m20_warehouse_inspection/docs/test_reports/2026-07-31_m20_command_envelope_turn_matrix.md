# 2026-07-31 M20 官方策略冷启动转向矩阵

## 试验边界

本报告只验证以下直接链路：

```text
精确 Twist -> 官方 rl_deploy_cmdvel -> 官方 M20 MJCF -> MuJoCo
```

未启动 SCAN、导航适配器、碰撞保护与巡检状态机。每个指令格均重新启动
MuJoCo 与官方策略，采用 1 秒斜坡、2 秒恒指令、1 秒减速及 1.5 秒停车观察。
稳定线为机身倾角不超过 `0.25 rad`、机身高度不低于 `0.48 m`，且无后端故障与
障碍接触。

## 对运动适配的结论

旧适配器把协调转弯的前进速度压到 `0.05 m/s`。该输出正位于矩阵反复出现的
低机身不稳定区，解释了“规划路径存在但 M20 跟踪时倾倒/偏离”的现象。

新的默认策略为：

- 高曲率时不再削减本来已经足够的前进速度；
- 高曲率或近原地偏航请求低于稳定区时，转换为至少 `0.35 m/s` 的滚动弧线；
- 最大前进速度仍为 `0.45 m/s`，最大偏航仍为 `0.65 rad/s`；
- 转换后的候选命令仍先进入下游实体足迹碰撞预测，空间不足时不得下发；
- SCAN-Planner、占据栅格与膨胀参数均未因此修改。

在最大偏航下，默认指令中心线半径约为
`0.35 / 0.65 = 0.54 m`。按机身 `0.82 m × 0.51 m` 的矩形外廓估算，完整稳态
转向的外侧扫掠半径约 `0.89 m`，直径约 `1.79 m`。因此 `0.9 m` 障碍间距只代表
直行通道条件，不能保证在通道内完成 90° 或 180° 转向；路线拐角还需单独保留
转向扫掠空间。

十个格均无障碍接触或后端故障。矩阵说明负向接口合法且姿态稳定，但响应不是线性
对称模型：

- `-0.20 m/s` 及以下基本落在反向死区；
- `-0.35 m/s` 直退能稳定产生约 `-0.12 m/s` 的有效运动，适合作为短时脱困动作；
- 低于 `0.35 rad/s` 的反向偏航响应明显偏弱；
- 反向转弯同样存在方向相关的正侧向漂移，所以碰撞恢复默认只使用直退，不把反向
  转弯作为安全动作。

运动适配层据此对普通 SCAN 反向跟踪请求增加局部死区逆补偿，但始终限制在生产
接口的 `±0.45 m/s` 和 `±0.65 rad/s` 内。碰撞保护的直退恢复则直接使用经过本表
验证的 `(-0.35,0,0)`，并在每个周期重新检查完整双圆扫掠包络。

## 单障碍集成回归状态

首次把方向相关漂移和直退动作接入完整 SCAN/M20 链后，180 秒单障碍回归得到：

- 最小连续保护余量 `0.0976 m`；
- `CURRENT_FOOTPRINT=0`；
- MuJoCo 障碍接触事件 `0`、峰值接触力 `0 N`；
- 10 次预测停车均找到碰撞检查通过的恢复动作；
- 任务未完成，原因是恢复方向在前向滚转和直退之间随离散栅格边界切换，比例爬坡
  反复从零开始，而不是碰撞或 A* 把机器人判为已在障碍内。

随后在碰撞保护节点中增加恢复方向锁存：已选方向只要从当前位姿重新预测仍安全，就
保持不变；若完整扫掠变为不安全则立即撤销。该实现已通过 `m20_inspection_core`
全部 72 项测试。新的完整冷启动回归结果为：

- 任务完成，用时 `170.24 s`，终点误差 `0.0610 m`；
- 最小连续保护余量 `0.0583 m`，最小 SCAN 实体半径净空 `0.1083 m`；
- `CURRENT_FOOTPRINT=0`；
- MuJoCo 障碍接触事件 `0`、峰值接触力 `0 N`；
- 最长连续指令静止由未锁存时的 `33.96 s` 降为 `2.74 s`；
- 共出现 134 次预测停车，说明系统已安全通过，但临界栅格上的
  `COLLISION_STOP/CLEAR` 状态仍过于频繁，性能不能判定为最优。

因此本阶段“不会进入实体/保护包络并能完成单障碍任务”的安全目标通过；后续效率
优化应针对保护状态去抖和恢复完成判定，不能通过缩小实体半径或 SCAN 膨胀参数来
掩盖。
